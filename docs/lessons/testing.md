# Lessons: Testing and tooling

How the tests run under node, driving a tab, shader text in tests, the dev server holding files.

Moved here from CLAUDE.md's "Things that took a long time to learn" on 2026-11-19, word for word and in their old order. Add a new lesson about this area here, never to CLAUDE.md. A code comment that cites "CLAUDE.md" or "the lesson in CLAUDE.md" means one of these files: grep `docs/lessons/` for its words.

- Node's type stripping runs the tests, and it does not take a TypeScript parameter property (`constructor(readonly x: X)`), nor an extensionless relative import: a runtime module that wants a node test writes its fields out and imports `'../core/physics.ts'` with the extension. `src/core/physics.ts` and Rapier itself load fine under node, so a test can build a real physics world and try the thing rather than a mirror of it. And the file that breaks need not be the test: a display file that grows an import of its own takes down whichever suite reaches it while `npx tsc --noEmit -p .` stays perfectly clean, so every value import under `src/` carries its extension whether a test names that file or not.
- `__debug.advance(s, keys, true)` keeps its keys down until a later call names them without `hold`; a test that presses a key with `hold` and then calls advance with other keys still has the first key down (a crouch held rolls, then crouch-walks; a trigger held never releases a charged shot).
- **Never tell a driven tab it is visible.** The game compiles with `compile` rather than `compileAsync` in a hidden tab because a hidden tab never reports a program linked; a harness that overrides `document.hidden` gets `compileAsync`, whose poll never finishes, and every dressed body stays `loading` and the next loading screen waits for good, which reads exactly like a hang in the looks. Stand in for `requestAnimationFrame` and the timers, never for the visibility. The stand-ins must be in place before the app boots, and an ES module already evaluated in a window is never evaluated again: so the tab goes first to a same-origin page that is not the game (any missing file under `assets-private/`), installs them, puts the address back to `/` with `history.replaceState` and only then writes the fetched `index.html` in. Written over the running game instead, the page comes up empty with the old `__debug` still answering.
- **A node test that reads a shader's text has to compile something of it too.** The blade glow pass once declared `own` twice in one scope of `bladeLight`, which every GLSL compiler refuses: the whole pass stayed unlinked in every browser, and every node test passed, because they matched expressions in the shader's source and node compiles no GLSL. `bladeGlow.test.ts` now builds the real source and scans it for a name declared twice in one scope -- following braces, and a function's parameters, which share its body's scope in GLSL ES 3.00 -- after checking the scanner on the very fault it was written for. A test that pins a shader by its text pins its words, not its program; whatever it cannot compile it should at least scan for what a compiler would refuse.
- A running Vite dev server holds the files it has served open, and on Windows that makes a conversion's swap of a pack folder fail with `EPERM` -- once it deleted a mobiles unit outright. Stop the dev server before converting anything.
- **Node's `performance.now()` allocates, so a node measure of a frame call that reads the clock reads 20 to 48 B a frame no browser would** (the GPU port's pass 1, wave 1, maker A: `ledgerFrame` in `src/core/gpu/pipeLedger.ts`, `tools/swg/tests/gpuLedger.test.ts`). Node builds `performance.now()` on `process.hrtime()`, which hands back a fresh array each call, and the twelve-process measure showed it in every process. The cure that is right for the browser too is to keep the clock out of the steady frame altogether: the frame call compares the travel's flag and stores two values, reads the clock only on the frames an arrival begins or its screen goes, and the arrival's thirtieth-second look at the warm-up's queue runs on a timer of its own, never in a frame. Measured so, every state of the call reads the harness's own floor (0.12 B) in 12 of 12 processes run at once.
- **A field begun at `-Infinity` (or `NaN`) makes every sum with it a double, and a double sum boxes in code not yet optimized: the twelve-process measure then flakes one process in two** (the GPU port's pass 1, wave 1, maker B: `ShipHud.rest` in `src/ui/shipHud.ts`, `tools/swg/tests/hudHide.test.ts`). The hide key's `rest` on the flight display first advanced its clock of seconds (`clock += dt`) and read 14 to 49 B a call in half the processes and 0.12 in the rest, even with `%GetOptimizationStatus` saying the function was optimized; moved to the page's clock in milliseconds, the same measure still read 7 to 17 B in half of them, because the window's start was declared `-Infinity`, so `now - restAt` was a double however whole the stood-in clock's numbers were. Begun at nought, as the display's own window starts, it reads 0.12 to 0.16 B in 12 of 12. The display's and the roster's `rest` were clean from the start because their windows begin at a clock reading. So for a frame call measured in node: carry the clock as the stood-in whole milliseconds (`performance.now` stood in with a function of the test's: node's own allocates, the lesson above), begin every field it is compared with at a whole number, and keep fractions out of a call that must make nothing; a fraction measured clean in one process proves nothing about the next.
- **A test holds only the forms of a fault it was handed, so it is proven by breaking the code the way the fault would, one way at a time, and watching it fail** (the GPU port's pass 1, wave 1, its review and fix round: `hudHide.test.ts` and `anchorScan.test.ts`). The hide key's test held every `refresh` by the bars and the rows that moved while hidden, and passed with six of its two-state records turned over instead of read back from the page (the very mistake the wave had made once): a turned record is wrong only when the truth turned while hidden, and the test turned only three. Each record now has a case where its truth turns while hidden, both ways, and all twenty-eight records across the display, the roster, a ship's instruments, the jobs, the minimap and the course's labels were each turned into a flip in turn, the test run and the file put back by its bytes (the fix round's script, `A:\swg3js\port\scratch\p1w1-fixer\mutate.ps1`): every flip fails. The anchor scan was a line of patterns a rule, each stopping at the first `)` or `;`, so a uniform made of `new Vector3().setFromMatrixPosition(mesh.matrixWorld)`, the camera's `.position`, an `eye.x` and a place reaching a 32-bit array a statement later all passed; it now reads each call's whole argument across lines, counts an object's place and a camera's or eye's components as world places, and follows a name filled from one to the end of the block it was filled in. Followed through the whole file instead, a name like `t` or `f` filled in one function counted in every other, and a right-hand side that was a function counted its body's reads, which over the existing world files flagged 122 lines, nearly all of them nothing; scoped, the same files give 18: fourteen of three's world nodes in the base's own programs, a world matrix set into a uniform, an instance placed at a world place, a view-space place made from a world matrix, and one distance from a world place written to a 32-bit array, the one line there that is no place at all. Every form the review found is planted in the test's own check, and every form that keeps to the rule is planted as let through.
- **The whole run is parallel, and a failure in the crowd is not yet a failure** (2026-11-19: `tools/swg/tests/runAll.mjs`, `npm run test:par`). The one-at-a-time `test:all` took 41 minutes and grew with every feature while using one core of sixteen. The runner reads the chain out of `package.json` each time (so it cannot drift from it), expands `npm run` steps in place, starts the longest suites first from the last run's times (`node_modules/.cache/swg-test-times.json`), and gives a suite that starts a relay on a fixed port (`const port = 18797`) a lock on that port, since two suites share one. The allocation measures flake under load, so a suite that fails among the others is run again alone at the end and fails the run only if it fails there too; the summary names the suites that failed only under load. Run it once at the end of a wave, never just after the groups it already covers.
