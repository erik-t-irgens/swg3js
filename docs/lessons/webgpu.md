- **The game can draw on three's WebGPU renderer behind a switch read once at boot, and with the switch at WebGL nothing of it is loaded and every guarded line is the one it had** (the GPU port's step 3: `src/core/gpuSwitch.ts`, `src/core/gpu/`, `gpuOff.test.ts`). `?renderer=webgpu`, else `localStorage['swg.renderer']`, else WebGPU (the default since 2026-11-18, when the owner made the port the trunk; `?renderer=webgl` is the old renderer). The WebGL boot loads one module of the port, `gpuSwitch.ts`, which imports nothing of three's but types; the WebGPU side is one dynamic import the boot makes only with the switch at WebGPU; and every site that draws otherwise asks `GPU.webgpu` and keeps its old line whole as the WebGL branch, held as text and by the boot's module graph in `gpuOff.test.ts`. Compared once against the commit before it by every WebGL program's source, three's `#define SHADER_NAME` line must be taken out first: it carries the name of whichever material first built the program, which differs between two sessions of one build, so compared whole a hundred programs read as changed that were not. Six things about three 0.187's WebGPU renderer. **A classic material is drawn through a node copy three makes of it** (`library.fromMaterial`, once a pipeline), whose uniforms read the original's fields by reference and whose render state (stencil, depth test, side, blending, polygon offset) is compared at every draw, so a uniform or a state written in place reaches the draw with no version step, and a picture swapped in place is a new binding three's observer finds by its id at the next draw (but not inside a render bundle, which binds what it was recorded with: below); an `onBeforeCompile` is never run there, so every injection of ours (the client's highlight, the wet look, the detail map, the card light, the sway, the cascades' shader) is simply absent on WebGPU, and a `ShaderMaterial` or `RawShaderMaterial` it cannot copy at all: a stand-in made once is registered on `userData.gpuStandIn` (the sky dome, the lava, the ground's tile program, the doorways' depth reset) and every other draw of one is stepped over in the renderer's own `renderObject` and counted by name (`fallback.ts`), or three logs and draws nothing. **`compile` is a getter handing back `compileAsync`**, which draws through `renderObject`, so an instance's own `renderObject` sees a warm-up's draws too. **A shadow map is drawn once a frame per camera, on the frame counter three's own animation loop moves from its first `render()`**, never by the game's passes, so the portal renderer's shadow-only draw is a no-op there and the rooms' lamps are asked for by `needsUpdate`. **`CSMShadowNode` fits its cascades to the camera it is first built with and takes the projection to be reversed when the renderer is**: built before the camera's own projection was turned, its boxes came out kilometres long or centimetres short and the near ground stood in shadow, so the camera is turned reversed before its `_init` (`sun.ts`). **The stencil reference is set at a draw only when the material writes the stencil**, and the stencil holds across `render()` calls into the canvas's multisampled target, which is what lets the portal renderer's passes run as they stand. **Three's counters are reset only by its own animation frame**, so they are read as what they rose by between the game's frames (`endFrame`); and `info.render.calls`, which the WebGL frame puts back to nought as its passes begin, is never put back on WebGPU (the next lesson). And the game's own `history.replaceState` drops every query on the address, so `?renderer=` is written back after it, or a reload would draw on WebGL.
- **On WebGPU the warm-up lists what three would draw by three's own walk and builds it off the frame, the region tiers draw from render bundles, and the four private patches of three's this needs are held to three's text** (the GPU port's step 3, its second half: `patchWarm.ts`, `bundles.ts`, `patchStencilBundles.ts`, `patchShadow.ts`, `patchStill.ts`, `patchTable.ts`, `patches.ts`; `gpuPatches.test.ts` holds every method a patch replaces or leans on to a hash of its 0.187 text, and `patchApplies` refuses any other revision). Seven things learned. **A pipeline is three's per render object, never per material**: its key carries the scene the pass draws through and that scene's lights, the side (a blended two-sided thing is drawn back then front), a morphed geometry's own morph attributes, `receiveShadow` and a skeleton's bone count, so the warm lists by three's walk (`compileAsync`'s synchronous half with `_createObjectPipeline` swapped for a list) and a burst's dedupe must carry every part of the key it can tell apart: keyed without the scene and its lights, a body's rooms pass (`passScenes.ts`'s proxy) was taken for its world pass and built at its first draw, 85 pipelines in one step into the cantina, none after. **Three's walk skips anything hidden** (`visible === false`) and the game prepares its bodies hidden, so a root that is not a scene has its drawables held under a holder, shown and unculled for the walk and put back. **A sun cascade is warmed by the same walk through its own shadow camera with its override material** (`getShadowMaterial`) and the adjustments three's `renderObject` makes per caster, and a cascade's map exists only once a program lit by the sun has been built, so a world's first items are built first. **A pipeline's landing is the GPU process's**: on a cold profile about one a second on Direct3D 12, so a first arrival waits minutes and every wait is bounded (`WARM_TUNE.landMs`). **A material whose render state flips between draws is a pipeline every flip**: the portal renderer's doorway polygon turned its depth test off and on between draws, 288 pipelines a second at the cantina's doors, so on WebGPU the restore and no-depth draws use a clone of their own (`drawPortalsGpu`). **Three replays every bundle after every draw that is in no bundle, never culls inside one (`_bundleDepth`), and a render bundle has no stencil reference**: the stencil patch notes the reference while a bundle is recorded and runs each with the one its materials carry now, after the pass's opaque draws and before its blended ones (run at the pass's head it was painted over by the sky's dome, which three draws first with no depth test), so the port bundles a tier's bulk opaque instanced meshes on layer 0 alone, tests each bundle against the view and the sun's shadow reach itself, and shows them only in a pass that sees layer 0. **A bundle's replay uploads no attribute and binds the pictures it was recorded with**, so its signature (`sigOf`) carries each mesh's matrices' version and its material's pictures by identity, and a level group's repack, a folded row hidden in place or a picture swapped reaches the GPU when the bundle is recorded again at the streamer's next poke. **Three's own `static` is never set on a game mesh**: it skips the observer's comparison, so an instance matrix written in place (a folded row) would never be uploaded; the port's mark is `userData.gpuStill`. And a skinned mesh's joints stay floats on WebGPU too: unsigned joints fail the pipeline's validation against the shader's float attribute.
- **On WebGPU three's `info.render.calls` is its own id of the render call, and the game's `DynamicDrawUsage` hint means "upload again every render call"; neither is what the WebGL code took them for** (the GPU port's step 3, its fix round: `main.ts`'s frame, `usageHint.ts`). Fixed, three's reading of `DynamicDrawUsage` cost what the bug had hidden: such an attribute is written to the GPU again in full every render call that draws it, and an instanced mesh whose matrices carry it is refreshed in full on every draw and every bundle replay (`hasDynamicInstancing`); at Mos Eisley's street, in one session turn about, the render call's median was 10.3 to 10.7 ms with the hint kept and 6.0 ms without. The game bumps a version at every write, as WebGL needs, so on WebGPU the hint is dropped as it is set (`BufferAttribute.setUsage` on the prototype, before any world is made; three's own dynamic nodes set theirs on an `InterleavedBuffer` or the field directly) and an attribute is written when its version moves: `__debug.gpu({ dynamicHint: true })` puts it back live, `localStorage['swg.gpu.dynamicHint'] = '1'` at load.
