# Lessons: The converter and the archives

IFF tags, animation tables and their marks, hardpoint and template formats, status stamps, Core3 and NGE references, SOE's final names list, entries of ours.

Moved here from CLAUDE.md's "Things that took a long time to learn" on 2026-11-19, word for word and in their old order. Add a new lesson about this area here, never to CLAUDE.md. A code comment that cites "CLAUDE.md" or "the lesson in CLAUDE.md" means one of these files: grep `docs/lessons/` for its words.

- **An IFF tag is always four bytes, so a three-letter tag carries a trailing space, and `childrenOf` matches it exactly.** This has now cost the project twice in the same file. `VAL ` below is the first; the second was `DIR `, the animation tables' direction selector, read as `'DIR'` fourteen lines above the comment explaining the trap. Every direction selector therefore returned an empty list, and so did every time-scale and probability selector standing over one: 358 of the game's own animation names were silently deleted across 23 tables, and on the body table every playable species shares that was exactly the 34 aimed blaster stances, standing and kneeling, and every whole-body blaster shot. Nobody in the game could aim because the poses were never converted, while `player.ts` and `npcs.ts` asked for them by pattern and fell back on the last frame of a transition -- a freeze, not a missing-animation error, which is why it never looked like a converter fault. Worse, `status` had been *blaming the archives in print*, telling the owner the retail table was smaller and to convert without `--retail-only`; the four duplicate names plus these 34 are exactly the difference it was reporting. Direction codes are a bitmask (4 front, 8 back, 1 right, 2 left) and are never 0; reading 4 as "front" is an inference from the file names, which end `_front` there, and from the sub-selectors, which sit on that branch and nowhere else, and it lives in one function so it can be overturned in one place. **Before trusting any tag comparison in a reader, count the letters.**
- An animation table's string selector (SSAT) keeps its value list in a chunk tagged `VAL ` (three letters and a space), not `VALS`: an i16 count, then each value's name and the i16 index of the branch it picks; several values share a branch. The converter names branches for their first value (`loop_riding:vehicle_speeder_bike`, `skill_action_5:dance_18`), the default branch plain, and writes every branch's values to the manifest as `variants`; `rig.variant(base, value)` resolves them in the game.
- An animation file (`.ans`, `FORM CKAT > 0001` or `FORM KFAT > 0003`) may carry a `FORM MSGS` saying when things happen inside the clip: an `INFO` count, then one `MESG` per message, each an int16 frame count, a name and that many int16 frame numbers. 3,399 of the 8,587 retail animations carry one (3,308 of 8,351 before SOE's final names list) and every one parses to the byte, which is checked on every file of every run rather than once by hand. A clip's frames are numbered 0 to one less than its count, and 1,524 marks sit exactly on the count: one past the last keyframe, which is the clip's last instant and a looping clip's wrap, so a reader must expect it rather than call the file corrupt. The shot marks (`fire1..fire11`), the hardpoint effects, the cinematic camera cuts and the marks that put a weapon in a hand and take it away are the code's already and are left out, which leaves the footsteps, the voices and the blows landing. A mark's time is `frame / fps` from the clip's own rate, not the fraction times a glTF clip's duration, which is exact only for a looping clip. Jedi Academy's own marks are in `models/players/_humanoid/animevents.cfg`, in an `UPPEREVENTS` and a `LOWEREVENTS` block, and their frames count from each animation's own first frame and not from the shared `.gla`; both of its humanoid config files must be read from the archives the game ships and from nothing else, because any `.pk3` dropped into the folder overrides them and a mod that doubles a walk's frame count puts a footstep a quarter of a cycle out. The other direction is caught by checking every clip's frame count against the clips already converted for the player, so it shows in `status` instead of in the feet. A name written with `%d` is drawn from every index range the event lines give it, and the extension a sound is named with is not always the one in the archives -- it slips both ways -- so every lookup tries the other before calling a file missing, as Jedi Academy's own loader does. A mark's chance is Jedi Academy's own convention and not a fraction: it is out of a hundred and nought means always, so 516 of the 519 marks in the pack carry nought and reading the field as a fraction dropped every footstep, voice and effect it has, leaving only the three lines that carry 30.
- A skinned mesh's hardpoints are `SKMG > <version form, 0004> > FORM HPTS > STAT` (and `DYN `, with a trailing space): an i16 count, then per hardpoint its name, its parent joint's name, a quaternion (w, x, y, z) and a position, in that joint's frame; every one in the retail archives parses to the byte this way. The `creatures` command writes them as `hp:<name>` nodes under their joints, mirrored exactly as the joints are (q to (w, x, -y, -z), x to -x). The mounts the game really let players ride (`datatables/mount/valid_scale_range.iff`) are exactly those whose mesh carries a `saddle` hardpoint; for the bantha, kaadu, bol and rancor only the `_hue` appearance the mount tables list carries it (the plain one has identical geometry and none), so it is read from there when both share a skeleton. The other creatures in the saddle map have no hardpoint and get a saddle on the back as measured posed.
- A mesh's BOX chunk holds its two corners with the larger first: read as min then max, every pack's `bounds` came out with min and max swapped (`readBounds` in `msh.mjs` now takes them componentwise; packs converted before carry the swap, so game code must take extents as `Math.abs(max - min)` and never trust which corner is which). The weapons rack's "far end" was on the wrong axis because of it, which is what made a measured aim correction turn the guns 90 degrees.
- A template's integer parameters carry a delta byte (' ', '+', '-' or '%') between the int8 data type and the int32 value: `intParam` in `objtemplate.mjs` reads offset 2. A gun's `weaponEffect` (bolt, rocket, projectile_rifle, ...) and `weaponEffectIndex` name a row of `datatables/weapon/weapon.iff`, which names the shot's `.prt`, the muzzle flash and the hit and miss client effects per surface; the weapons command converts those into the pack and writes them as each gun's `fx`. The flame throwers are bolt 21 (a fireball), the lightning rifles rocket 3 (the lightning beam), the slugthrowers `projectile_*`.
- In `iff.mjs`, `childrenOf(node, name)` needs the name and returns nothing without it; to walk every child, iterate `node.children`. A form's name is `node.type` (`node.tag` is always `FORM`).
- **What the converter reads from the emulator ships with it, and nobody installs the emulator** (the owner's decision: it is referenced, not taken). `travel`, `fittings`, `deeds`, `spawns`, `snapshot`, `pois` and `mobiles` read `tools/swg/core3ref/` -- the twelve Core3 readers' answers (names, places, turns, counts and stats, never the scripts, credited to SWGEmu Core3 under its AGPL-3.0 in the folder's `index.json`) -- and read a folder live only when given `--core3=<dir>` outright, never from `.env`, so a checkout and every launcher convert exactly the same thing. `core3-reference @CORE3` writes it, and compares every answer, over every zone the screenplays name and one for any other, with a fresh read of the folder before it keeps anything; measured, `travel`, `fittings`, `deeds` and `spawns` write byte-identical packs either way. Run it when Core3's scripts change and commit what it writes. The launcher's release carries it (`pack.mjs`), and the launcher test fails if a file of it goes missing, since a folder read by path is invisible to the import check. `regions/regions.json` was the first file of this kind. Older comments saying nothing read from the emulator may reach the repository are about the converted packs, which still never may.
- **SOE's final names list is the difference of two mounts, applied after the install's own indexes, all of it or none, and everything converted says which mount it came from** (`tools/swg/finalnames.mjs`, `finalnamesBuild.mjs`, `openVfs`'s late phase in `tre.mjs`, the list `tools/swg/manifests/final-names.json`; SOE complete, wave 1). An NGE install holds every archive SOE shipped, but its four indexes stop at publish 54, so 7,063 files and 2,815 newer copies sat unreached in archives the player owns. The list is SOE's final four `.toc` files mounted over the same archives less the install's own (9,880 `set`, 8 `deleted`, 2 `gone`), keyed by twelve hex of the SHA-1 of its text with every line ending folded to LF, written only by the maintainer's `final-names` and checked row by row against an install by `final-names --verify`. The gate is exact: the indexes hash to the list's `against` and all 17 archives it reads stand at the final-client manifest's size and SHA-256, or nothing is applied and the mount is the one before to the entry (`none`, `refused`; a folder holding SOE's own indexes is `final`). Two rows are held back, the Life Day snow terrains of Tatooine and Talus. Every command that opens the archives writes `late` (`{ key, state, rows, v }`) into the file `status` reads for it (`LATE_STAMPED`; `LATE_EXEMPT` says why each other command needs none), and every path that keeps a model because its file is there asks `keptStale`, never `materialStale` alone (a text pin in `finalNames.test.ts`). Seven things learned. **`status` hashes no archive**: `probeInstall` reads the install's four index files and its archives' sizes, the install is `--swg`, else `SWG`, and an empty `SWG` names none, which PowerShell cannot say (`$env:SWG = ''` deletes the variable), so every test that runs `status` over fixture packs hands its child `env: { ...process.env, SWG: '', SWG3JS_PLACEMENTS: '' }` (the second since the race drawer's first wave, so the owner's live edit files in this checkout never reach it), or on a machine whose `.env` names an install the probe says serves it sees the late asks as well. **A late ask never names `--jka`**: the plan reads an ask that names it as one that needs Jedi Academy and skips it on a machine without. **A test that holds a pack's pixels or counts to the archives opens them as that pack was converted, which its own stamp says** (`mountForPack`, `mountForLate` in `materialsHarness.ts`), and a count a re-issued file moves is pinned per late world (the props pack's size cap, the dye floors, the saddle count and the armoured varactyl's saddle, Dathomir's radial affectors, Tatooine's tiers and furniture, the hair grids), or the first suite run between one conversion and the next fails on packs that are right: the normal-map test found a re-issued fan texture 18 degrees off a weapons pack converted before. **The mobiles' source key takes the late world only where the list applied** (`sourceStampOf`), so a mount it does not serve keeps today's key to the bit; and because the code stamp re-keys no unit, nothing `mobilesCodeStamp` reads may change once the real run has been made. **The rewritten check counts a file as named only by a JSON at or above its own folder** (`rewrittenCheck`): by name anywhere in its top folder, 798 female meshes an older run left in the human male wardrobe read as named by the female wardrobe's JSON, and a run that was right failed. **A refusal records what it saw, and `status` asks again for it only once that has moved** (the stamp's `seen`, each refused archive's size and when it was written, against the probe's `archives`; `lateAsk`): the probe reads sizes and the mount SHA-256s, so on the probe's `serves` alone a byte flipped at SOE's own size, or an archive this machine cannot open, was "this install can now mount SOE's final files" in every `status` and a whole conversion redone in every `convert`, refused each time; a folder whose only packs are such refusals says the stamp's why on its line, and one with no pack converted says nothing is converted rather than "mounted in every pack". **What makes a walk grid stale is one function** (`gridLayoutStale`), which `status` and `navgrid --skip-existing` both ask, since a resumed bake that read only the version, the angle and the rules kept exactly the grids `status` then asked for again.
- **What a menu shows of SOE's final files is asked of the menu's own function, keyed on the pack's own stamp, and four of the menus' rules met the late tables only through that** (`src/ui/lateReport.ts`, `__debug.late()`, `tools/swg/tests/lateMenus.test.ts`; SOE complete, wave 2). The console's `late()` reads only what the game has already fetched (a wardrobe through `Character.wardrobesNow`, the garage's `late`, the props', the deeds' and the creator table's own) and asks the very products the node test asks of the packs on disk, where a pack with no stamp is a note and one stamped `applied` fails when its menu does not show the late thing. **SOE's final table gives each Wookiee and Sullustan gender the other's styles on the very same meshes**, so the other gender's group is deduped by mesh as the untabled one always was, which empties it for both Wookiees and for a Sullustan man (a Sullustan woman keeps his beards and his styles 20 to 27) and moves two grids nobody asked about, four styles each way out of the Bothans' other gender's group and the Zabrak men's 25 out of a Zabrak woman's, every one on a mesh an earlier cell already shows (`hairGrid.test.ts` holds every species' grid to the pass's base: the base's less only such cells of the other gender's group, and nothing new); the own group stays the table's rows to the letter, so the two rows the table itself names on one appearance (the Zabrak man's 21 and 25) stand twice there, and the test says so as a note. **A beard is numbered from 1 as the styles are**, so twelve of a Sullustan man's cells read what twelve others read until `styleLabel` said "Beard N". **The one hair entry `isHairKey` still missed was the Singing Mountain Clan's bangs** (`singing_mountain_clan_bangs_s01`, under a hair folder of its own), found by holding every wardrobe's hair entries to it. **A dial's line could not write a tier**: `movedArgs` passed over a path part that was not a name, so the NPC ship ladder's `grade.8` would have vanished from the line the menu copies out; a whole number is a key it writes now (`src/space/tierDials.ts`). And the give tab puts an entry no id pattern places under its arrangement's first slot (`slotGroupOf(id, slots)`, the slots' groups ours), while the Clothes panel's group "take off" asks the same (`WardrobeUi.groupOf`), or a piece listed under Back by its slot would never have been taken off by Back's own button; and since a group then gathers several body slots (a ring and a cybernetic hand under Hands, a wrist bracelet under a bracer), a double-click on a worn piece takes off that piece alone (`takeOff`), where taking off its whole group would have taken the cybernetic hand off with the gloves. The test reads the packs through the code's own rules and never a looser copy of them (the garage's `garageGalleryRows`, the NPC tab's `readinessOf`), and a ships pack whose `combat.json` is missing does not show the tier 10 type, which `late()` tells from a file not yet landed by the fetch's own `ShipContacts.loaded` and names in `missing` (`missingMenus`). The check of the final table's two new hair groups (the Wookiees' fur, holding the pattern, and the humans' `hair_trim`, whose colour only nine of the men's styles and twenty of the women's carry) found nothing the page drew wrong: the grid stands in the first hair group (`gridGroupId`, which the page now asks) and a later one shows its own rows or nothing.
- **The NGE reference is the copy's answers, not the overlay's packs, and it is proved by building the overlay from both** (`ngeref.mjs`; SOE complete, wave 6). A pack's rows join each player's own catalogue, ground and rooms, so what ships is the reader's answers cut down to exactly what `buildNgeOverlay` asks (`extractNgeReference`: each placed row's kind, name in its table, place, turn and the objvars its kind is read for, as positional arrays; the crews; the regions and lists; and only the creatures, type tables, `.tpf` bodies, dress lists, stats, weapons and lairs the rows name), read back by `ngeRefReader`, which answers every method `makeNgeReader` has, and the one proof that matters is the overlay built over the same packs from a fresh read of the copy and from the reference just written, with the archives and without, equal in every row, name and count (`writeNgeReference`, `comparable`, which strips only where it came from and when): 533 KB against W3's 9 MB of packs. Four things the first cut would have got wrong. The copy's placed objects are read only for the frame check and are 12,656 rows, so the measurement is made once when the reference is written and kept in its index (`frames`, handed to `zoneOverlay` as `frameObjects`). A row of a table with no `objid` was named by its whole text, which carries its scripts and objvars, so `rowIds` names it by sixteen hex of that text's hash, which moved those rows' keys (`NGE_FORMAT` 2, so `status` asks again). A crew's row naming no creature and no table is a thing in the room to the overlay (`things`), never `unresolved`, so a count of what names nothing must read both. And a test of `status --json` must assert that status ran: a stand-in catalogue without `failed` and `options` throws inside `packStatus`, the JSON is empty, and "asks no spawns" passed on nothing. Three more the review found. The reference's hash folds every line ending to LF before it hashes (`referenceHash`), as the names list's key does, since a checkout with `core.autocrlf` (the owner's) checks the files out CRLF and the test that holds the index to its files stopped every suite there. A test that two builds name every row alike proves only that the build is one function twice, unless the two are built over machines that differ: built over a catalogue missing one body in seven, every row the second build keeps still has its name (`ngeReference.test.ts`), which is what naming by key bought. And a check that the reference keeps "only the creatures its rows name" must work that set out again from the rows, never compare a count with the count the same run wrote: a writer copying the copy's whole creature table passed it. **Mustafar's arrival is the world's own, named on its definition** (`PlanetDef.arrival`, `src/world/arrival.ts`): a raw place, an absolute height and a heading in the game's frame (a body faces `(sin h, cos h)`), turned into the game's frame from the places file's centre before the world is in (`App.homeOf`, awaited in `play` and `travel` as the teleport awaits its centre), the spawn a death comes round at, never moved to open ground (`clearSpawn`, which on the deck is the valley about 125 m below) nor lifted to the terrain, and left as the spawn by a ship come down out of space (`arrivalHome`). **A respawn there is a move further than a walk**: the deck is a building's collision, which the streamer makes only near the player, so a death far from it that stood the player straight back on the spawn stood them in the air over the valley to fall 125 m; with no floor under the spawn now (`spawnNeedsWorld`, one short ray) it comes round as at a facility (`standAtHome`: a loading screen, the world moved there, `settle`, the floor read, the ground under it said in words should the deck not come in), and so does the console's `arrival({ go })`. Its type lives in `src/data/planets.ts` itself and `arrival.ts` imports it from there: `planets.ts` ships with the server, and the release's own check reads even a type written `import('../world/arrival.ts')` as a file named and refuses a release that leaves it out, which only the launcher's suite, the last of `test:all`, sees.
- **What SOE's last publishes added and nothing names is stood from a table of ours, a skeletal prop is posed once and drawn still, and the NPC-only ship appearances are hulls the garage never lists** (SOE complete, wave 7: `tools/swg/manifests/ours-entries.json` read by `tools/swg/oursEntries.mjs`; `bakePose` in `skeletal.mjs`; `npcOnlyHullPicks` and `END_OF_WAR` in `npcships.mjs`). Of the 66 appearance files the final names list brings that no template, table or string names, 46 are rows of a committed table of ours (a path, a menu, a name of ours, a garment's client arrangement and the bodies anything worn fits; nothing of the client's words) and 20 are left out with their reasons in `OURS_LEFT_OUT`. `wardrobe`, `customization`, `mobiles` and `props` stand each row as they would a template's entry, with `ours: true`, a null `template` and an id no template could give (`ours_`, `hair_ours_`, `ours/`), each stamps the table's key (`ours`), and `status` asks again under another key only where SOE's final files were mounted, by the names list or by an install's own final indexes (`oursAsk`, asked before the loop's `applied`-only named products). **Anything that reads an entry's `template` takes it as possibly null** (`propStandOf`, `?? undefined` where a template is handed on, the closet's test). Four things were learned. **A file no template names may still wear exactly what a template's file wears**: eight of the census's 66 are a second `.sat` over a template's own meshes (the Bothan mohawks, the bangs, a human style, two Wookiee beards, the Love Day wings, and a "Bothan" style that is a Sullustan woman's mesh), which `lateMenus.test.ts`'s mesh check found on the pilot, so they are left out, and `oursEntries.test.ts` holds every wardrobe folder to it across folders (a hairstyle of one species can sit in another's folder). **A garment the game wore only through a body is worn over that body** (a row whose `fits` names a body path: the Togorian's and the Ugnaught's dresses, each an appearance of its own, `ours_<stem>`), while what a body's own `.sat` already wears is left out (the Dug's wearables, the reek's nose ring), and a dressed NPC of the game's may now find a garment of ours for a mesh its client data names (five of them, the Singing Mountain holograms and Han's vest), so `wardrobeIndex` takes a game item first for any mesh both wear; and a garment of ours names only the palettes a recipe of it reads (the Kubaz goggles' lens shader names one no recipe can render, which `dyeConvert.test.ts` caught; every piece of the game's own already holds to it). **This wave is the one deliberate full rebuild of the mobiles**: the bodies of ours and the `wear` they carry change `mobiles.mjs` and `skeletal.mjs`, which `mobilesCodeStamp` reads and which re-keys no unit, so the table's key is a stamp of its own on the catalogue (`ours`, written by any run not narrowed by `--only`, `--match` or `--limit`) and `status` asks for the plain run, which makes every unit again (3 min 43 s on the pilot), only of a catalogue carrying no such stamp: one planned with an earlier table is asked for `--skip-existing`, which plans again, renames and redoes only a unit whose signature moved, so editing the table's names never costs another rebuild; the game's own units keep their signatures (a body's `wear` goes into its signature only where it has one). And `__debug.ours` was already the people's, so the console's helper is `oursEntries()`. **A skeletal prop** (a prop template whose appearance is a `.sat`, every one of which `props` skipped before: the creature statues, the armour on stands, the trophies) is skinned on the CPU in its own table's idle at the first frame, else at its bind pose (`--skeletal-pose=bind` stands every one so, and the pose asked is written into the manifest, `skeletalPose`, and kept by every later run that names none, as `--no-dye` is, or the first run `status` asked for anything else stood them back at their idle), set on its lowest point and written with no skin under a model id of its own (`<family>_still`: a family drops the extension, and a skeletal `at_st.sat` and the Hoth AT-ST display's static `at_st.apt` were one model, so the display wore the walker), so the streamer instances, casts, culls, places and picks it up as any prop and it builds no program of its own: 438 props in 366 models, 221 MB and 50 s; the idle reads better for anything on two legs or perched (a Jawa, a hawk bat) and the same as the bind for the four-legged, which is why it is the default and the owner's to change. **The NPC-only hulls** go through the very `buildShips` a player hull goes through, with no interior, named `npc_<family>` (the family of the template picked for that appearance, the first family in sort order and its lowest tier: `npc_decimator` on `vt49_npc.apt`, `npc_eow_rebel_transport` on `shuttle_rebel_lg.apt`) and marked `npc`, which the garage's lists and counts step over: 23 hulls, 111 MB and 10 s, which takes the types from 295 to 410. `combat.json`'s `endOfWar` lists the End of War capital ships and stations (the type, its hull, its side, a name read off the type's own name table or its template's `objectName`): the corvette and both Star Destroyer types on the garage's own hulls, the lancer, the Nebulon frigate, the rebel transport and the two GCW stations on NPC-only ones; the NPC tab's End of War group stands them through `standHull` at a tier of their own (`END_OF_WAR_TUNE.tier`, 5), never in a zone's patrol. **The NPC tab stands everything at one distance along the view**, so three of them stood one after another from one spot (a Lancer, a transport, a GCW station) stood inside each other and wrecked each other within seconds of the tab shutting, which no test of a stand alone could show: a hull bigger than a fitted one is now refused in words wherever a place of its layout would stand inside an NPC ship already out or still being built (`standsInside` over `inTheWay`, which counts the places every stand from the tab holds from before its first wait until it is done: a capital ship takes seconds behind its hold, and two quick presses stood the second inside the first), asked before the group is made in `standHull` and in a big family's stand and never of a fighter, and a stand never moves a layout further out, since `hullLayout` alone decides how far a member stands and so how far it is drawn.
- **`player`, `parts` and `species` stamp no format on what they write**, unlike the mobiles packs, so `status` cannot tell an old rig from a new one and nothing will ever ask for them again on its own. That hole has now bitten twice: once leaving nineteen of twenty species unable to swing a lightsaber, and once leaving every rig without an aimed blaster pose. The answer both times is to name a clip the new conversion must produce and look for it (`jkaClips` for the first, `loop_*combat_standing_aimed` for the second -- and *standing*, because the prone aimed loops survived the `DIR ` bug and searching for "aimed" alone finds twelve clips and proves nothing). Any converter change that alters what those three commands write needs a check of that shape, or the owner's install silently keeps the old thing for ever.
- `convertParticle` caches per output pack. Before, a run over several planets wrote later planets' manifest entries for particle effects without their files.
- **`readLua` reads tables and steps over everything else; it never throws.** The emulator's town screenplays define their spawn tables beside functions (`spawnMobiles`, and inside them `local pMobile = spawnMobile(self.planet, mob[1], ...)`), and the reader threw on the first `function` in 32 of the 35 city files; `core3.mjs` caught the error and moved on, so for two passes no town had anybody standing in it and nothing said so. `tools/swg/lua.mjs` now steps over a `function ... end` body and over any top-level statement it cannot read, counting each (`skipped`), which reads all 35 and took the worlds from 4,619 standing people to 10,358, and the screenplay's own `self.planet` is read from the file's table rather than guessed. A file of the emulator's that reads to nothing is a count in the converter's report, never a caught exception. Two more traps came out of the same run: `getRandomNumber` folded to a constant stood 216 people on one point, so a row that asks for a random place is drawn apart once from its own key; and a creature flagged `KILLER` or `STALKER` is not one that attacks on sight -- read that way, 864 of the towns' people opened fire on everybody walking in.
- A mobiles model that fails with "no mesh survived" is one the game's own archives strip at every detail level (the gubbur): a rerun fails it again, so `status` lists it apart and does not count it as work (`permanentFailures` in `mobiles.mjs`), but only while the failure was recorded from the archives the catalogue was made from and for the unit signature it plans now.
